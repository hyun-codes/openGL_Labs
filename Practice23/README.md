# Practice23

VAO·VBO와 모델·뷰·투영 행렬을 사용하는 로봇 걷기 실습이다.
Visual Studio에서 Practice23을 시작 프로젝트로 지정하고 x64로 실행한다.

## 조작

| 키 | 기능 |
| --- | --- |
| W / A / S / D | 앞(-z) / 왼쪽(-x) / 뒤(+z) / 오른쪽(+x)으로 방향을 바꾸고 계속 걷기 |
| + / - | 걷기 속도 조절. = 키와 숫자패드도 지원 |
| J | 점프. 공중에서는 다시 점프하지 않음 |
| O | 무대 앞면 열기/닫기 |
| I | 로봇·문·카메라 초기화 및 장애물 3개 재배치 |
| z / Shift+z | 누르는 동안 카메라 z축 음/양 방향 이동 |
| x / Shift+x | 누르는 동안 카메라 x축 음/양 방향 이동 |
| y / Shift+y | 무대 중심 y축 주위로 카메라 공전. 같은 방향을 다시 누르면 정지 |
| Q | 종료 |

## 코드 흐름

`main → InitBuffer → ResetScene → 반복(Update → DrawScene)`

입력 함수는 방향·속도·토글 등의 상태만 바꾼다.
Update 함수들은 시간에 따라 상태를 갱신한다.
Draw 함수들은 현재 상태를 변환행렬로 바꾸어 그린다.
15·16번처럼 로봇 전체 행렬과 각 부위의 관절 행렬을 곱한다.

## 기능별 구분

| 기능 | 상태 | 상태 갱신 | 그리기 |
| --- | --- | --- | --- |
| 문 열기 | isFrontOpen, frontOpenAmount | UpdateStage | DrawStageScene |
| 로봇 이동 | position, direction, rotateAngleY, walkSpeed | UpdateRobotMovement | DrawRobotScene |
| 팔·다리 흔들기 | walkPhase, limbSwingAngle | UpdateRobotWalking | DrawRobotLimb |
| 점프·착지 | position.y, jumpVelocity, isGrounded | UpdateRobotJump | DrawRobotScene |
| 카메라 | Camera 구조체 | ProcessCameraInput, UpdateCamera | DrawScene의 view 행렬 |

Robot 구조체에 로봇의 상태를 모아두고, Obstacle 구조체 배열에는 장애물 3개의 위치·크기·색을 저장한다.
Mesh는 공통 헤더에 있는 VAO·VBO 묶음이다. 로봇의 부위와 장애물은 같은 육면체 버퍼를 재사용한다.

## 변환행렬

로봇 전체는 `이동 × 방향 회전`으로 배치한다.
각 팔다리는 `로봇 전체 × 관절 이동 × x축 회전 × 부위 중심 이동 × 크기 조절`로 그린다.
행렬의 오른쪽부터 정점에 적용되므로 팔·다리가 자신의 관절을 중심으로 흔들리고, 그 결과가 로봇 전체와 함께 이동한다.
같은 쪽 팔과 다리는 반대 방향으로, 양쪽 다리도 서로 반대로 흔들린다.
속도가 증가하면 걷는 주기와 최대 흔들림 각도가 함께 증가한다.

앞면은 윗부분을 기준으로 y축 스케일을 줄여 아래 모서리가 위로 올라가게 한다.
무대는 안쪽이 정면인 여섯 평면으로 구성한다. 뒷면 컬링을 켜면 밖에서 보는 가까운 벽은 사라지고 안쪽을 보는 먼 벽은 남는다.
따라서 기본 카메라에서는 앞면이 컬링되어 문 변화가 잘 보이지 않을 수 있다. 카메라를 무대 안쪽이나 반대편으로 이동하면 확인할 수 있다.

## 충돌과 점프

CanMoveTo는 다음 위치가 무대 범위 안인지, 장애물의 옆면과 겹치지 않는지 검사한다.
막히면 해당 위치로 이동하지 않고 방향을 180도 바꾼다. 문이 열려도 로봇은 무대 안에서 걷는다.
공중에서 로봇의 발이 장애물 윗면보다 높으면 그 위로 이동할 수 있다.
하강하면서 윗면을 지나면 그 높이에 착지하고, 장애물 밖으로 걸어나오면 바닥으로 내려간다.
J는 수직 점프 속도만 추가하며 기존 걷기 방향은 유지한다. 공중에서도 WASD로 방향을 바꿀 수 있다.
로봇이 장애물에 가까이 갔을 때 J로 뛰고 방향을 맞추면 올라갈 수 있다.
판정은 로봇 전체를 둘러싼 단순한 범위를 사용하며 팔다리 각각의 충돌은 계산하지 않는다.

Update는 이동·점프를 작은 시간 간격으로 나눠 처리한다. 문과 카메라의 상태는 프레임마다 한 번만 갱신한다.

깊이 테스트·뒷면 컬링·원근 투영을 사용한다. 별도의 물리 엔진, 모델 파일, 텍스처는 필요 없다.
